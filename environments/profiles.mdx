The browser profile inside an environment stores persistent Chrome data — cookies, local storage, extensions, cache — that carries over between sessions. Attach an environment to a session and it starts with your saved state already loaded instead of a blank browser.

**Without a profile:** Every session starts fresh. You log in each time, re-accept cookie banners, and lose any site-specific state.

**With a profile:** Sessions pick up where you left off. Login cookies persist, site preferences carry over, and previously saved data is available immediately.

---

## Common Use Cases

### Skip Repeated Logins

Log in once, then reuse that session across future tasks:

1. Create an environment
2. Run a session with the environment attached and log in to the target site
3. The environment saves your login cookies in its profile
4. Future sessions using this environment start already authenticated

### Preserve Site Preferences

Carry over cookie consent choices, language settings, dark mode preferences, and other site-specific configuration between sessions.

### Maintain Cart or Workspace State

For e-commerce or SaaS workflows, keep cart contents, workspace configurations, or application state intact between sessions.

---

## How Profiles Work

### Lifecycle

```
Create Environment → Upload Profile Data (optional) → Use in Sessions → Download / Update → Delete
```

1. **Create** an environment via the API. Its profile starts with status `empty`.
2. **Populate** the profile by [syncing from your local machine](/environments/sync-profiles), uploading a `.tar.gz` archive via the [Environments API](/environments/environments-api#upload-browser-profile-data), or by running a session with the environment attached — the browser state saves automatically.
3. **Use** the environment by passing its ID when starting a session. The browser loads the profile's saved data before executing any tasks.
4. **Delete** the environment when you no longer need it.

### Profile Status

| Status | Description |
|--------|-------------|
| `empty` | Created but has no browser data yet |
| `uploading` | Data upload in progress |
| `ready` | Has browser data and can be used in sessions |

---

## Using a Profile in a Session

Pass `environmentId` as a parameter when starting a session or running a task:

```bash
curl -X POST https://connect.webrun.ai/start/run-task \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "environmentId": "<ENV_ID>",
    "taskDetails": "Go to amazon.com and check my order status"
  }'
```

<Tip>
Environments with profile status `ready` load saved browser state immediately. If you attach an environment with status `empty`, the session starts with a clean browser and the profile is populated when the session ends.
</Tip>

---

## Limits

- Maximum **20 environments** per user
- Maximum upload size: **500 MB** per profile
- Accepted upload format: `.tar.gz` or `.tgz`
- Download URLs expire after **1 hour**
